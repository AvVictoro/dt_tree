Работа выполнена в отдельном репозитории `AvVictoro/dt_tree` и ветке `feature/catalog-ux-experiments`. Перенос исходной оболочки зафиксирован отдельным базовым коммитом `54f0050`; функциональные изменения идут после него. Репозиторий `AvVictoro/DTTTT` не изменялся.

## Слои

1. `catalog/main.mjs` — четыре интерфейса и общие карточки.
2. `catalog/api-client.mjs` — единый клиент API.
3. `server/catalog-service.mjs` — одинаковая семантика запросов для локального сервера и Vercel.
4. `catalog/demo/catalog-demo.json` — автономный реальный набор из 14 355 индикаторов.
5. `migrations/001_catalog.sql` — production-схема PostgreSQL с полнотекстовым, trigram и фасетными индексами.
6. `scripts/catalog/import_full.py` — потоковый versioned-импорт полного каталога.

## Решение по объёму

Полные исходные CSV занимают несколько гигабайт в распакованном виде и не подходят для статического клиентского bundle. Поэтому:

- автономная версия содержит 14 355 реальных записей, покрывающих все 15 блоков;
- интерфейс всегда показывает полные контрольные объёмы отдельно от размера локального набора;
- полный набор загружается в PostgreSQL/Neon импортёром без попадания гигантских архивов в Git;
- API-контракт одинаков для локального и полного режима.

## Данные и графики

Архивы содержат классификационные метаданные, а не значения наблюдений. Поле `has_time_series=false` сохраняется явно. Карточки не строят синтетические графики и не подменяют отсутствующие наблюдения.

## URL и история

Состояние каталога хранится в hash route, например:

`#/catalog-2?block=BLOCK_09_FIN_MARKETS&topic=...&frequency=M`

Back/Forward восстанавливают представление и фильтры. Карточка хранит возвратный маршрут и состояние выборки.

## Что требуется для полного production-режима

Нужна только строка подключения `DATABASE_URL` к отдельной PostgreSQL/Neon базе для проекта `dt_tree`. Без неё полный импорт намеренно не выполнялся; локальная версия полностью работоспособна и автономна.
